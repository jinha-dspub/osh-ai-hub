# OSH AI Hub · 공통 UI/UX 디자인 가이드

버전 1.1 · 2026-09-19

새 AI 도구의 화면을 사용자와 개발자가 같은 기준으로 논의하기 위한 문서다. 현재 Hub의 짙은 파란색 디자인을 출발점으로 삼는다. 기존 화면 전체가 아래 기준을 충족한다는 뜻은 아니다. 색상과 공통 클래스는 현재 구현 기준이며, 접근성·작업 흐름·상태 표시는 새 화면에 적용할 설계 기준이다.

## 앱 간 시각적 통일: OSH Family Design

다른 앱도 osh.ai.kr와 같은 색상·폰트·카드·버튼으로 보이게 하려면 [OSH Family Design](../design/osh-family/README.md)을 기준으로 한다. 공통 CSS·예시 화면·로컬 한글 폰트를 묶어 다른 앱/AI에게 전달할 수 있다. **색·형태는 공유하고 화면 배치는 앱의 기능에 맞춘다.** 이 문서는 상세 UX·상태·접근성 기준을 제공한다.

## 1. 디자인 방향

**차분하고 읽기 쉬운 연구·업무 도구. 무엇을 입력하고, 어떤 결과를 얻으며, 결과를 어디까지 믿을 수 있는지 명확하게 보여준다.**

- 첫 화면에서 도구의 목적, 입력 방식, 실행 가능한 기능을 파악할 수 있게 한다.
- 한 작업 영역에 가장 중요한 기본 행동은 하나만 둔다.
- 흰색 작업 화면, 짙은 파란색 주요 행동, 충분한 여백을 기본으로 한다.
- 실제 자료, 합성 예시, AI 생성 결과와 아직 연결되지 않은 기능을 구분한다.
- 장식보다 입력·결과·근거를 먼저 배치한다. 본문에 기술 스택이나 저장소 이름을 불필요하게 노출하지 않는다.
- 모바일에서도 입력부터 결과 확인·다운로드까지 같은 작업을 마칠 수 있게 한다.

## 2. 색상과 형태

아래 값은 `web/app/globals.css`의 현재 토큰이다. 기존 토큰을 우선 사용한다.

| 토큰 | 값 | 용도 |
|---|---|---|
| `--primary` | `#003876` | 기본 버튼, 선택 상태, 주요 링크 |
| `--primary-soft` | `#e6effb` | 선택된 항목과 옅은 강조 배경 |
| `--navy` | `#06264c` | 짙은 브랜드 영역 |
| `--ink` | `#14243d` | 제목과 본문 |
| `--muted` | `#52627a` | 보조 설명 |
| `--line` | `#d6e0ed` | 테두리와 구분선 |
| `--paper` | `#f5f8fd` | 페이지의 보조 배경 |
| 표면 | `#ffffff` | 카드와 입력·결과 영역 |
| DEMO 배지 | 배경 `#fff2d6`, 글자 `#785209` | 합성·예시 콘텐츠 표시 |

- 카드 모서리는 기본 12px, 버튼은 기존 7px를 따른다. 작은 배지는 기존 4px를 따른다.
- 카드는 얇은 테두리로 구분한다. 강한 그림자·다중 그라데이션·과도한 둥근 모서리를 반복하지 않는다.
- 브랜드 그라데이션은 소개 영역에 제한하고 작업 영역은 단색으로 유지한다.
- 아이콘은 기존 `lucide-react`를 사용한다. 일반 아이콘 18–24px, 도구 소개 아이콘 28–32px를 권장한다.
- 오류·성공·경고는 색상에 더해 문구나 아이콘으로 의미를 전달한다. 새 상태 색상은 대비를 확인한 뒤 공통 토큰으로 추가한다.
- `.teal`이라는 기존 클래스명도 실제로는 파란 계열이다. 이름만 보고 별도의 청록색 디자인을 도입하지 않는다.

## 3. 글꼴·간격·반응형

기본 글꼴은 기존 로컬 `Noto Sans KR Variable`이다. 코드·파일 경로에는 시스템 고정폭 글꼴을 사용한다.

| 요소 | 새 작업 화면의 권장 기준 |
|---|---|
| 페이지 제목 | 데스크톱 32–36px, 모바일 26–30px |
| 작업 영역 제목 | 20–24px |
| 본문·입력 | 16px, 줄높이 1.6–1.8 |
| 보조 정보 | 14px, 줄높이 1.6 이상 |
| 긴 설명 | 읽기 영역 최대 약 720px |
| 간격 | 4·8·12·16·24·32·48·64px 단위 |
| 카드 안쪽 | 데스크톱 24–28px, 모바일 16–20px |

현재 Hub에는 14px 본문과 더 작은 배지가 있다. 위 권장값은 신규 작업 화면의 가독성을 위한 기준이며 기존 전체 CSS 변경을 지시하는 것은 아니다. 중요한 동의·오류·제한 설명을 작은 글씨에 숨기지 않는다.

- 기존 컨테이너: 최대 1240px, 좌우 여백은 큰 화면 40px, 1150px 이하 24px, 640px 이하 18px다.
- 기존 반응형 기준인 1150·850·640px를 우선 활용한다. 새 작업 화면은 850px 이하에서 입력·결과를 한 열로 배치하는 것을 기본으로 한다.
- 휴대폰 입력 글자는 16px 이상, 주요 터치 영역은 최소 44×44px를 설계 기준으로 한다.
- 360px 화면과 200% 확대에서도 핵심 행동이 잘리거나 페이지 전체가 가로로 넘치지 않게 한다.
- 넓은 표·코드만 내부 스크롤을 허용하고 스크롤 가능 여부를 알 수 있게 한다.

## 4. 기본 화면 구조

도구 설명은 짧게, 실제 작업 영역은 첫 화면 가까이에 배치한다. 작업 화면마다 대형 홍보 배너를 반복하지 않는다.

```text
OSH AI Hub / 도구 이름                         이용 안내
도구 제목                         [DEMO 또는 확인된 기능 상태]
무엇을 입력하면 어떤 결과를 얻는지 한 문장

┌ 입력 영역 ──────────────┐  ┌ 결과 영역 ──────────────┐
│ 입력 설명 / 파일 선택   │  │ 상태 안내 또는 결과 요약 │
│ 선택한 자료와 유효성    │  │ 본문 · 표 · 시각화       │
│ 필요한 옵션             │  │ 출처와 한계             │
│ [주요 실행 버튼]        │  │ [다운로드] [다시 시작]  │
└────────────────────────┘  └────────────────────────┘
자료 처리 안내 · 도움말
```

이것은 구성 예시이며, 모든 도구를 두 칸에 맞추지는 않는다.

| 도구 유형 | 적합한 구성 |
|---|---|
| 변환·추출·분류 | 입력 → 실행 → 결과·파일 다운로드 |
| 자료 검색 | 검색창 → 필터·결과 목록 → 문서 상세 |
| 문서 기반 AI 질의응답 | 자료 범위 → 질문 → 답변과 확인 가능한 근거 |
| 여러 파일 처리 | 파일 목록 → 항목별 상태 → 성공·실패 구분 → 결과 다운로드 |

문서 기반 답변에서는 근거 문서명·절·링크를 표시한다. MD에 없는 페이지 번호를 만들지 않는다. XLSX 연결 정보를 활용할 때 연결되지 않은 문서는 누락 상태로 보여준다.

## 5. 공통 컴포넌트

기존 `web/components/ui.tsx`와 `web/app/globals.css`를 먼저 확인한다.

| 요소 | 기본 규칙 |
|---|---|
| `PageIntro` | 제목과 목적 설명. 페이지의 h1은 하나 |
| `DemoBadge` | 예시 콘텐츠 가까이에 DEMO 표시 |
| `.button` | 현재 작업의 주요 실행 |
| `.button.secondary` | 취소·뒤로·보조 행동 |
| `.tool-card` | 도구명, 한 문장 설명, 기능 상태, 바로가기 |
| `.info-note` | 실행 전 알아야 할 제한과 안내 |
| `EmptyState` | 상태 설명과 다음 행동. 문구와 행동이 맞지 않으면 확장 |
| `DataTable` / `.table-scroll` | 비교·검토할 구조화된 자료 |

- 작업은 button, 페이지 이동·파일 주소 이동은 링크로 구현한다.
- 입력에는 항상 보이는 레이블을 둔다. placeholder는 보충 예시로만 사용한다.
- 파일 입력은 클릭·키보드로도 사용할 수 있게 한다. 드래그만 강요하지 않는다.
- 확장자·허용 용량·전송 여부를 선택 전에 안내한다. 실제 검증 조건과 문구를 일치시킨다.
- 비활성 버튼에는 주변 설명을 둔다. 색이 흐려진 이유를 사용자가 추측하게 하지 않는다.
- 설명 없이 아이콘만 있는 버튼에는 접근 가능한 이름을 부여한다.

## 6. 반드시 설계할 상태

| 상태 | 화면과 행동 |
|---|---|
| 처음 진입 | 입력할 자료와 다음 행동 안내 |
| 입력 완료 | 파일명·용량·선택 항목 확인, 수정 가능 |
| 입력 오류 | 해당 입력 옆에 이유와 수정 방법 표시 |
| 업로드 중 | 실제 전송량을 알 때만 진행률 표시, 가능한 경우 취소·이어 올리기 |
| 처리 중 | 실제 단계 또는 처리 중 표시, 중복 실행 방지 |
| 성공 | 실제 반환된 결과, 다운로드 가능 여부, 다음 행동 |
| 일부 성공 | 성공·실패 항목을 분리, 실패 항목만 재시도 |
| 결과 없음 | 실패와 구분하고 입력·검색 범위 조정 안내 |
| 실패·시간 초과 | 사용자가 할 수 있는 복구 행동, 입력 보존 가능 여부 |
| 인증·권한 필요 | 필요한 로그인 또는 접근 요청 안내 |
| 연결 준비 중 | 연결되지 않은 기능 설명, 실행 불가 상태 |

측정되지 않은 완료율·대기 시간·정확도를 만들지 않는다. 실제 요청을 보내지 않았는데 로딩 애니메이션 뒤 성공을 보여주지 않는다. 재시도로 중복 제출이나 추가 비용이 생길 수 있다면 그 행동에 필요한 안내를 제공한다.

## 7. DEMO와 실제 AI의 표현

- 합성 자료·예시 결과·예시 수치는 해당 콘텐츠와 내려받은 파일에서 DEMO임을 식별할 수 있게 한다.
- 미리 만들어 둔 결과에는 `DEMO · 예시 결과`를 표시하고 현재 입력의 분석 결과처럼 연결하지 않는다.
- 실제 모델로 예시 데이터를 처리했더라도 데이터가 DEMO라는 표시는 유지한다.
- 연결되지 않은 기능에는 `모델 연결 준비 중`을 표시한다. 가짜 성공·회원정보·API 키를 제공하지 않는다.
- 실제 모델 응답은 AI 생성 결과임을 알리고 필요한 출처·대상 범위·한계를 가까이 표시한다.
- 신뢰도는 실제 모델이 반환하고 해석 가능한 경우에만 표시한다. 신뢰도를 검증된 정확도로 바꿔 쓰지 않는다.
- 실제 도구와 DEMO가 한 화면에 섞이면 항목별로 표시한다. 전체를 실제 서비스 또는 전부 DEMO라고 단정하지 않는다.
- 평가 수치·이용자 수·운영 실적은 확인 가능한 출처가 있을 때만 표시한다.

## 8. 데이터·접근성·문구

- 파일이 브라우저 안에서만 처리되는지, 서버 또는 외부 AI로 전송되는지 실제 동작에 맞게 안내한다.
- 데이터 공개, 연구 제출, 삭제처럼 사용자가 결정해야 하는 행동에는 대상과 영향을 표시한다. 실제 저장 완료 후에만 저장 완료를 보여준다.
- 민감정보를 포함한 화면을 공유할 때는 DEMO 자료로 대체한다. 개발용 스크린샷에 실제 참여자 정보를 사용하지 않는다.
- Hub의 초기 로그인은 Google만 사용한다. 외부 도구의 본인인증과 Hub 로그인을 혼동시키지 않는다.
- 키보드 탭 순서, 보이는 포커스, 레이블, 오류 알림, 결과 갱신 안내를 확인한다. 기존 포커스 색은 `#0e4a9f`다.
- 본문 대비 4.5:1 이상을 내부 검수 목표로 삼고 실제 조합을 측정한다. 옅은 경계선만으로 입력 위치나 상태를 구분하지 않는다.
- 불필요한 움직임을 줄이고 `prefers-reduced-motion` 설정을 존중한다.
- 한국어 버튼은 구체적인 동사를 쓴다: `자료 선택`, `문서 변환`, `질문 보내기`, `결과 다운로드`.
- 오류는 원인과 다음 행동으로 쓴다. 예: `파일 형식을 읽을 수 없습니다. MD 또는 XLSX 파일을 선택해 주세요.`

## 9. 사용자와 디자인을 공유하는 방식

새 도구마다 [디자인 브리프 양식](DESIGN-BRIEF-TEMPLATE.md)을 복사해 목적과 화면 구성을 정리한다. 미정인 항목은 가정으로 표시하며, 모든 항목을 사용자에게 한꺼번에 질문하지 않는다.

공유 자료는 기본적으로 다음 세 가지다.

1. 한 문장 목적, 입력과 출력, 주요 행동, 실제 연결 범위.
2. 데스크톱·모바일 화면 또는 간단한 배치도. 초기·처리 중·결과·오류 상태 포함.
3. 아직 미구현인 부분, 사용자 결정이 필요한 부분, 검증 결과.

시안은 되돌릴 수 있는 로컬 미리보기에서 확인한다. 사용자가 이미 정한 선택은 반복해서 묻지 않고, 일반적인 간격·버튼 배치는 이 가이드로 결정한다. 화면 공유와 운영 배포 여부는 구분해 보고한다.

## 10. 완료 기준과 유지관리

- 목적과 기본 행동을 첫 화면에서 이해할 수 있다.
- DEMO·실제 결과·미연결 기능이 구분된다.
- 입력·처리·성공·빈 결과·오류·권한 상태를 확인했다.
- 360px 모바일과 데스크톱에서 잘림 없이 작동하고 키보드로 주요 작업이 가능하다.
- 출처, 다운로드 내용, 자료 처리 안내가 실제 동작과 일치한다.
- UI 구현 변경은 lint·typecheck·관련 테스트·build를 실행한다. 브라우저 동작 변경은 데스크톱·모바일 검증을 포함한다.
- 로그인·저장·다운로드 권한 변경은 보안 경계를 검증한다. 디자인 문서만 바뀐 경우 테스트를 새로 만들지 않는다.
- 새 공통 규칙을 채택하면 이 문서와 실제 컴포넌트를 함께 갱신한다. 특정 도구만의 예외는 그 도구의 브리프에 이유를 남긴다.
