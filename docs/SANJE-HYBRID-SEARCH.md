# 산재 DEMO 자연어·하이브리드 검색

작성일: 2026-09-21 · 데이터 버전: 2026-09-19.v1
기준: [디자인 가이드](DESIGN-GUIDELINES.md), [브리프 양식](DESIGN-BRIEF-TEMPLATE.md)

## 목적과 화면

연구자가 “지하 탄광에서 오래 일하면서 먼지를 마신 사람의 만성 폐질환 사례”처럼 작업 상황을 문장으로 입력해 관련 사례를 탐색한다. 단어가 모두 포함되어야 했던 키워드 검색만으로는 이런 질문에 결과가 없었다.

기존 OSH Family Design의 색·글꼴·검색·상세 배치를 유지한다. 검색 방식의 기본값은 **자연어 · 하이브리드**, 대안은 **키워드 · 원문 포함**이다. 빈 검색어는 모델을 호출하지 않고 필터에 해당하는 전체 목록을 제공한다. 연도·판정·직종·대조 상태의 다중 필터를 먼저 적용한다.

결과는 최대 200개 **관련 후보**로 표시한다. 필터 대상 전체 수와 후보 수를 구분하며 결과 존재가 실제 인과관계나 산재 인정 가능성을 의미하지 않음을 기존 안내와 함께 표시한다. 모델 또는 인덱스 장애 때 자연어 검색 성공을 흉내 내지 않고 오류와 키워드 검색 대안을 안내한다.

데스크톱과 모바일의 순서는 검색 → 필터 → 후보 → 원문·라벨·근무시간 확인이다. 모델 생성 답변을 검색 결과로 만들어 넣지 않는다. 브라우저 자동화의 자료는 DEMO 합성 fixture다.

## 검색 방식

1. 선택 질환·현재 릴리스에서 필터에 맞는 행을 선택한다.
2. 로컬 EmbeddingGemma가 질문을 768차원 벡터로 변환한다.
3. 해당 행들에서 코사인 유사도 상위 200개와 한국어 문자 2-gram/단어 BM25 상위 200개를 각각 구한다.
4. 두 순위를 Reciprocal Rank Fusion(`1/(60+rank)`)으로 합치고 상위 200개를 20개씩 제공한다. 동점은 원본 행 순서로 정해 페이지 이동 결과를 안정적으로 유지한다.

의미 검색 인덱스의 입력은 **원래 직종·AI 표준 직종·유해인자·AI 요약을 순서대로 합친 첫 700자**다. 원문 전체나 라벨 전체를 임베딩한 것이 아니다. 원문에만 있는 세부 문구는 키워드 검색에서 확인해야 한다. 키워드 검색은 기존처럼 공백으로 구분한 검색어를 모두 포함하는 원문·주요 필드를 찾는다.

모델: `embeddinggemma:latest`, 고정 digest `85462619ee721b466c5927d109d4cb765861907d5417b9109caebc4e614679f1`, 768차원, L2 정규화. 문서 접두어는 `title: 산재 판정사례 | text:`, 질문 접두어는 `task: search result | query:`다. [공식 모델의 검색 프롬프트 규약](https://ai.google.dev/gemma/docs/embeddinggemma/model_card#prompt-instructions)을 따른다. [Ollama embed API](https://docs.ollama.com/api/embed)에서 자동 잘림을 끄고 오류를 확인한다. 임베딩 처리 배치 상한도 문맥 길이와 같은 2,048 토큰으로 설정해 긴 문서가 512 토큰 배치 상한에 걸리지 않게 한다.

## 데이터·인증·비용

원문과 질문은 로컬 서버에서 처리한다. 검색에 유료 외부 API를 호출하지 않는다. 기존 .3 관문 인증·Origin 검사·입력 크기 제한을 유지한다. Google 로그인만으로 연구자료 접근 권한을 부여하지 않는다.

인덱스는 Git 제외된 `local_asset/sanje/<version>/search-embeddinggemma-v1/<group>/`에 저장한다. 원본 스냅샷과 배포 ZIP은 변경하지 않는다. 질환·자료 버전·cases.csv 해시·모델 digest·입력 규칙·벡터/ID 파일 해시·행 매핑·정규화를 로딩 시 확인한다. 맞지 않으면 의미 검색을 차단한다.

운영 질문 임베딩은 기존 CPU Ollama `127.0.0.1:11435`를 이용한다. 모델 단일 동시 실행과 기존 일일 200회 AI 호출 제한을 공유한다. 동일 질문은 프로세스 메모리에 최대 256개 캐시하며 원문·검색어 로그를 만들지 않는다. 질환별 결과는 별도로 계산해 필터·질환 경계가 캐시 때문에 섞이지 않는다.

## 생성과 적용

```bash
SANJE_RELEASE_CONFIG=/home/shield/osh-ai-hub/local_asset/sanje/2026-09-19.v1/release.json \
  ai-api/.venv/bin/python ai-api/scripts/build_sanje_search.py
```

기본 생성도 기존 로컬 CPU 모델을 사용한다. 이번 일괄 생성에는 기존 서비스를 변경하지 않는 임시 loopback GPU 서버 `11436`을 사용한다. 모델 파일은 이미 설치된 동일 digest를 사용한다. 생성 종료 후 임시 서버와 그 모델 프로세스만 종료한다.

64행마다 체크포인트를 저장한다. 다른 자료 해시·모델·규칙으로 기존 체크포인트를 재사용하지 않는다. 모든 질환이 완성된 뒤에만 후보 release.json에 인덱스 경로를 추가한다. 운영 포인터를 원자적으로 교체하고 기존 `osh-demo.service`를 재시작한다. .3 nginx와 기존 운영 포트는 유지한다.

프런트는 `npm run build:copd-demo --workspace web`로 빌드한다. Vercel 소개 화면과 .6 DEMO 서비스 배포는 별도 단계다.

## 검증 범위

- 자동 테스트: 문장 완전 일치가 없어도 의미 후보 반환, 필터 우선 적용, 빈 검색·빈 후보의 모델 호출 생략, 최대 후보 수·안정된 페이지, 모델 실패, 버전/모델/질환/원본 해시 불일치, 인증 우회 차단.
- 웹: 자연어 모드 기본 요청, 다중 필터와 상세·라벨·파일 흐름, 데스크톱/모바일 및 기존 기능 회귀 검사.
- 실제 자료: 질환별 자연어 질문과 기존 키워드 결과를 비교한다. 관련 단어가 상위 후보에 있는지의 기능 점검은 전문가 정답셋을 사용한 검색 정확도 평가가 아니다.
- 한계: 전체 질환의 전문가 관련성 평가·동시 다수 사용자 부하 시험은 별도다. 임베딩 대상 700자 밖의 세부 정보, 부정 표현과 시간 관계는 원문에서 확인해야 한다.
