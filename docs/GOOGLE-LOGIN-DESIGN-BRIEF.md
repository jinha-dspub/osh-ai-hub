# Google 로그인 디자인 브리프

작성: 2026-09-19 · 상태: 구현·로컬 검증 완료, 운영 실계정 검증 대기
기준: [공통 디자인 가이드](DESIGN-GUIDELINES.md)

## 목적

OSH AI Hub에서 Google 계정으로 로그인하고 본인의 계정·권한을 확인한다. Gmail과 Google Workspace를 함께 허용하며 메일함·Drive 권한을 요청하지 않는다.

## 입력과 결과

| 항목 | 결정 |
|---|---|
| 입력 | Google에서 계정 선택. Hub에서 비밀번호를 받지 않음 |
| 주요 행동 | Google로 계속하기 |
| 결과 | 요청하던 사이트 내부 화면으로 복귀. 직접 로그인 시 내 계정 |
| 다운로드 | 이번 범위에 없음. 기존 연구자료 접근 관문은 별도 |
| 개인정보 | Supabase Auth가 계정 기본 프로필·이메일 및 세션을 관리. UI는 검증된 이메일·권한만 표시 |
| 권한 | Supabase getUser 검증. 관리자 여부는 role_assignments 조회, 조회 실패·테이블 미설정 시 일반 회원 |

## 화면 구성

데스크톱·모바일 모두 상단 로그인 → 한 열의 로그인 카드 → Google 계정 선택 → 원래 화면 / 내 계정. 로그인 후 상단은 내 계정. 계정 화면에 이메일, 일반 회원/관리자, 데이터 둘러보기, 현재 브라우저 로그아웃.

| 상태 | 화면·행동 |
|---|---|
| 미로그인 | Google로 계속하기, 로그인 없이 둘러보기 |
| 이동 중 | 버튼 중복 제출 차단, Google로 이동 중 |
| 설정 없음 | 준비 중 안내, 비활성 버튼 |
| 취소·오류 | 고정 안내 문구, 재시도. 외부 오류 원문은 표시하지 않음 |
| 로그인 성공 | 서버에서 검증한 내 계정. 가짜 인증 성공 없음 |
| 로그아웃 실패 | 계정 화면에서 재시도 안내 |

## 보안·실제 연결 범위

- PKCE code 교환, HttpOnly/SameSite=Lax 쿠키, HTTPS 운영 Secure 쿠키.
- Next.js 16 proxy에서 getUser로 세션 검증/갱신, 갱신 쿠키는 요청과 응답 모두 반영.
- 개인화된 응답은 private/no-store. callback은 no-referrer.
- 로그인·로그아웃은 POST이며 APP_URL과 Origin 일치 필수. 반환 주소는 사이트 내부만 허용.
- 관리자 권한은 이메일·사용자 메타데이터·브라우저 플래그로 부여하지 않음.
- 새 DB 테이블·migration 적용 없이 Auth 계정 사용. 기존 role_assignments RLS는 별도 구성 항목.
- 로그인은 자료 공개 승인·연구 참여 동의·국가 본인인증을 대신하지 않음.
- 외부 DEMO /demo 경로와 기존 .3/.6 서비스·포트·인증 설정은 이번 범위 밖.

## 검증과 외부 설정

단위 테스트: CSRF, 안전한 반환 주소, 실패·취소·재사용 코드, 서버 사용자 검증, 로그아웃 오류, 쿠키 갱신, 관리자 권한 위조 거부.
브라우저 테스트: 데스크톱·모바일 버튼과 화면, 실제 PKCE 시작 쿠키, 비로그인 계정 페이지 차단, 콜백 취소, 직접 관리자 접근 차단. DEMO 설정으로 OAuth 시작까지만 검사하며 실제 Google 계정 인증 성공으로 간주하지 않는다.

설정: [Supabase·Google 설정 안내](SUPABASE-GOOGLE-SETUP.md). 실제 Google 계정 선택·동의와 운영에서의 세션 갱신·로그아웃 검증은 사용자 계정으로 완료해야 한다.

검증 결과: lint·typecheck·build 통과, 단위 테스트 35개, 기존 E2E 28개, 인증 E2E 6개 통과. 모바일 로그인 화면 시각 검수 완료.
