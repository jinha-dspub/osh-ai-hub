# COPD 데이터셋 등록·탐색 설계안

2026-09-17 · 논의용 초안. 외부 업로드, DB migration 실행, 검색 앱 실행, 운영 공개는 하지 않았다.
디자인 기준: [공통 디자인 가이드](DESIGN-GUIDELINES.md).

## 1. 로컬 자료 점검

`opendata/copd`의 15개 파일을 집계했다. 총 73,232,071 bytes(약 73.2MB, 69.8MiB). 이번 패키지에는 XLSX나 개별 판정서 MD가 없으며, 원문은 CSV에 들어 있다. README 3개 외 Markdown 문서는 없다.

| 구성 | 직접 확인한 내용 |
|---|---|
| cases.csv | 2,082행 × 20열, 사건번호 중복·누락 없음 |
| case_texts.csv | 2,082행 × 3열, 사례와 1:1 연결, 본문 길이 값 일치 |
| exposure_measurements.csv | 646행 × 23열, 79개 사례에 연결 |
| 연도 | 2016–2021 |
| 참조 무결성 | 원문 없는 사례·사례 없는 원문·사례 없는 측정치 0건 |
| 기타 산출물 | STATS.json, Parquet 임베딩, pgvector SQL, Python 검색 예제, FastAPI 웹 참조 구현 |

직접 검사한 범위는 CSV 구조·행 개수·키 연결·빈 셀·저장된 품질 플래그·개수 일치 여부다. 원문 해석, 익명화 적정성, 라벨 정답성은 이번에 전수 검증하지 않았다. Parquet 내부의 실제 벡터 차원·결측·정렬·모델 버전 및 SQL 실행 결과도 아직 검증하지 않았다.

## 2. 공개 설명과 내보내기에서 보완할 점

- 저장된 판정 대조 플래그는 일치 1,950, 불일치 3, 미대조 129건이다. 대조 가능한 1,953건 중 일치율은 99.85%, 전체 대조 가능 비율은 93.80%다. README와 STATS.json의 100% 표시는 반올림으로 불일치를 가리므로 수정 대상이다. 이 수치는 플래그 재집계이며 이번 작업에서 원문 대조를 재수행한 결과는 아니다.
- 직종 표준화 2,043/2,082 = 98.13%는 값이 존재하는 비율이다. 정확도 또는 나머지 39건이 오답이라는 뜻이 아니다.
- cases.n_measurements 합계는 650, 실제 측정치 행은 646이다. 두 사례가 각각 선언값/실제값 12/10, 13/11이다. 원인을 확인하기 전 원본을 임의 수정하거나 삭제하지 않는다.
- ICD 코드가 빈 사례는 2,070건이다. 필드 존재만으로 주요 필터에 노출하지 않고 채움 비율을 함께 제시한다.
- 원문 출처를 뜻하는 src_/raw_도 추출 과정의 오류 가능성이 있다. 화면에서는 ‘원문 기반 값’과 실제 원문 근거를 연결하고 자동으로 검증 완료라고 부르지 않는다.
- README는 자동 생성 파일이므로 .166의 내보내기 생성 로직에서 수정하고 재생성하는 방식이 적절하다. 현재 README·CSV·STATS는 그대로 두었다.
- 기존 자료의 라이선스는 미정이며 라벨 권리 귀속도 미확정이라고 README에 명시되어 있다. 출처의 이용 조건과 가공 라벨의 공개 범위를 구분해 확정한다. 특정 라이선스를 임의 선택하지 않는다.
- 원문의 개인정보 점검 통과는 반입 문서의 주장이다. 이를 독립 검증한 것으로 표시하지 않는다. 공개용 표·원문·요약·검색 문구까지 동일한 검수 범위로 다룬다.

## 3. 제품 방향

Hugging Face의 데이터 카드·구성별 표 보기·버전별 파일 배포 방식을 참고한다. Keras Datasets는 주로 학습용 데이터 로더 모음이므로 등록·운영 UI의 직접적인 본보기로는 Hugging Face가 더 가깝다.

OSH AI Hub를 자료 설명·검색·접근 제어의 주 화면으로 만들고 Supabase에 등록한다. 공개 조건 확정 후 Hugging Face에는 동일한 확정 버전의 파일과 카드를 배포하는 방식이 가능하다. 두 곳에서 따로 수정하지 않고 하나의 버전 manifest와 해시로 동기화한다. Hugging Face에 올리지 않아도 Hub에서 서비스할 수 있다.

현재 패키지는 실제 사례를 포함한 초안이다. 단순히 demo 폴더에 있다고 합성 자료로 분류하지 않는다. 실제 자료는 ‘실제 자료 · 검수 중’, 체험 기능은 ‘DEMO 검색’, 합성 예시는 ‘DEMO · 합성 예시’로 각각 표시한다. 기존 Hub의 모든 자료를 DEMO로 가정한 카드·푸터도 실제 자료 등록 시 수정 대상이다.

## 4. 저장과 적재

| 계층 | 역할 |
|---|---|
| Supabase Storage 비공개 dataset-files | 반입 원본과 확정 배포 파일. 버전별 경로로 보관 |
| 기존 datasets / dataset_versions / dataset_files | 설명·상태·공개 범위·버전·라이선스·용량·SHA256 |
| 신규 사례·원문·측정치 테이블 | 필터·페이지네이션·관계 조회. 별도 migration과 RLS 필요 |
| 별도 임베딩 테이블 | 버전·사례키·모델 식별자·차원·입력 텍스트 해시·벡터 |
| ai-api | 질의 임베딩과 검색 조합. API 비밀은 서버에만 유지 |
| web | 데이터 카드·검색 UI·다운로드 안내 |

사례 기본키는 (dataset_version_id, accnum)으로 잡고 자식 테이블에도 같은 버전을 연결한다. 행 순서로 파일끼리 매칭하지 않는다. 측정치에는 별도의 안정적인 행 식별자를 부여한다. SQL과 사례 테이블을 여러 버전으로 덮어쓰지 않는다.

`copd_pgvector.sql`에는 DROP TABLE이 있고 RLS 정책은 없다. 운영 Supabase에 그대로 실행하지 않고 필요한 스키마를 검토해 마이그레이션으로 다시 정의한다. 기존 스키마도 원격 적용 여부는 별도 확인해야 한다.

적재 순서: 로컬 검사 → 해시·버전 manifest 생성 → 비공개 저장소에 직접 전송 → 임시 적재 영역 검사 → 한 버전으로 DB 반영 → 내부 미리보기 → 공개 조건 충족 시 게시. 대용량 업로드·다운로드는 웹 함수가 중계하지 않는다. 파일 해시와 외래키 검사를 통과한 뒤에만 게시 가능 상태로 전환한다.

검색 API·미리보기·다운로드에도 동일한 버전 공개 범위와 권한을 적용한다. 관리자 권한은 서버에서 부여하며 브라우저 프로필 수정으로 얻을 수 없게 한다. 원문이 비공개라면 검색 요약으로 우회 노출되지 않게 한다.

## 5. 사용자 UI

상단: 제목 / 실제 자료·검수 상태 / 버전 / 기간 / 사례 수 / 자료 이용 행동.

탭은 5개로 시작한다.

1. **소개**: 출처, 가공 과정, 활용 범위, 선택 편향, 인용, 라이선스.
2. **데이터 보기**: 사례·노출 측정치·원문 테이블 선택, 필터, 열 설명, 결측 표시.
3. **사례 검색**: 키워드 검색과 검증 후 추가할 의미 검색, 결과에서 상세 열기.
4. **품질·한계**: 대조 가능·일치·불일치·미대조, 필드별 채움 비율, 측정치 보유 사례 비율.
5. **파일·활용법**: 버전별 파일 크기·해시·형식, Python 로딩 예제, 변경 이력.

```text
COPD 산업재해 판정 사례                   [실제 자료 · 검수 중]
2016–2021 · 사례 2,082건 · 측정치 646행 / 79사례
[소개] [데이터 보기] [사례 검색] [품질·한계] [파일·활용법]

[검색어 입력                                         검색]
[연도] [원문 기반 판정] [AI 표준 직종] [AI 유해인자] [검증 상태]

결과 목록                            선택한 사례 상세
원문 기반 판정 / AI 직종              원문 | AI 요약·라벨 | 노출 측정치
요약·검색 일치 근거                   대조 상태와 원문 확인
```

데스크톱은 목록·상세 2열, 모바일은 목록에서 상세 화면으로 이동하고 뒤로 가면 필터·스크롤 위치를 복원한다. 검색 조건은 URL에 보존하되 개인정보를 검색어에 입력하지 않도록 안내한다.

결과 상세는 원문 기반 값, AI 요약·표준화 라벨, 검증 결과를 구분한다. 불일치 3건·미대조 129건을 필터로 찾을 수 있게 한다. 초기에 사용할 주요 필터는 실제 채움 비율과 이용 목적을 보고 선정한다.

노출 측정치는 대상 사례 수와 측정 행 수를 함께 표시한다. 본인 사업장·유사 사업장·문헌 인용, 조사 주체·연도·통계 유형·단위를 구분한다. 누락을 0으로 채우지 않는다. 비교할 수 없는 단위를 한 평균으로 합치지 않는다.

원문 Markdown/HTML은 안전하게 렌더링하고 원시 HTML을 무조건 신뢰하지 않는다. CSV 다운로드에는 수식으로 해석되는 셀 처리 정책을 둔다. 생성한 합성 시안에는 반드시 DEMO를 표시한다.

## 6. 검색과 평가 방법

1차는 정확한 키워드·구조화 필터·원문 열람이다. 필터링된 전체 건수와 의미 검색 상위 N건은 UI에서 구분한다.
2차는 어휘 검색 + 벡터 검색 후 순위를 합치는 하이브리드 검색을 비교 평가해 추가한다. 정확한 유해인자 포함 여부가 필요한 경우 명시 필터를 제공한다.

기존 두 임베딩을 활용하되 같은 차원이라고 혼용하지 않는다. 실제 모델 식별자·리비전·입력 전처리·차원·질의/문서 작업 설정을 확인하고 문서와 호환되는 질의 벡터만 사용한다. 변경 시 새 인덱스 버전으로 관리한다.

데이터 제작 문서의 10개 질의 또는 4개 질의 평가는 좁은 시험 결과다. 일반 검색 정확도나 새 Hub의 성능으로 표시하지 않는다. 검색 정답 목록과 검토 기준을 만들고, 직종·유해인자·판정·측정 맥락·검색 결과 없음 등 유형별 질의를 분리한다. 조정용 질의와 최종 평가용 질의를 구분하고 평가 데이터·버전·모델·지표를 기록한다. Precision@k, Recall@k(관련 사례 목록이 확보된 범위), 지연시간, 실제 비용을 측정한다.

향후 모델 학습에서는 판정 주문이나 결과를 직접 드러내는 요약이 예측 입력에 들어가는 누출을 막아야 한다. 동일 사건·유사 중복 문서는 같은 분할에 두고 필요 시 시간 기준 평가를 한다. 현재 train이라는 로더 명칭만으로 검증된 학습·평가 분할이 있다고 보지 않는다. 개인별 산재 승인 확률을 제시하는 기능은 이 첫 버전 범위에 포함하지 않는다.

3차로 필요할 때 근거 기반 답변을 추가한다. 집계는 SQL/코드로 계산하고 답변은 출처와 함께 표시한다. 근거 없는 답은 결과 없음으로 처리한다. 외부 API 비용 통제·캐시·호출 제한은 운영 검증 후 연결한다.

## 7. 다음 결정

- 공개 다운로드가 목표인지, 승인된 이용자에게만 제공할지.
- .166에서 측정치 4행 차이와 품질 문구를 정정한 새 export를 받을지.
- 정확한 자료 제공자·가공 주체·라이선스·인용문을 어떻게 확정할지.

첫 구현 범위 제안: 비공개 내부 데이터 카드 + 표 미리보기 + 정확한 필터/원문 열람. 이 구성이 확정되면 승인된 배포 파일과 검색 인덱스를 연결한다. 미확정 항목이 있어도 원본을 공개하지 않는 내부 시안·검증 도구 작업은 진행할 수 있다.
