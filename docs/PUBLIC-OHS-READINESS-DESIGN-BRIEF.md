# 공공기관 안전보건 입찰 준비 점검 디자인 브리프

상태: 운영 중 (2026-10-01 관문 재시작, 화면 판본 react-c973d69315)
작성일: 2026-10-01
기준: [OSH AI Hub 디자인 가이드](DESIGN-GUIDELINES.md)

## 목적

- 사용하는 사람: 공공기관 공사·용역·물품 입찰에 참여하거나 공공기관 현장에서 일하는 업체(안전 담당자, 대표)
- 해결할 일 한 가지: 우리 업체가 공공기관 입찰·계약의 안전보건 기준을 어디까지 충족하고 무엇이 부족한지 근거와 함께 확인한다
- 도구 설명 한 문장: 하려는 일을 고르고 업체 정보를 넣으면(자연어 설명을 AI가 칸으로 옮겨 줌) 항목마다 충족·부족·확인 필요와 준비할 것, 근거 조항을 보여 준다
- 이번 작업 범위: 판정기준 데이터셋(NAS), 화면(/demo/public-ohs-readiness/), 기준 자료 내려받기

## OSH Family Design 적용

- 적용 키트 버전: OSH Family Design 1.0 (`design/osh-family/osh-family.css`), 추가 스타일은 `ro-` 접두사로 키트 토큰만 사용
- 앱에 맞게 달라지는 레이아웃/작업 순서: 1. 하려는 일(4개 카드, 여러 개) → 2. 업체 설명 AI → 3. 업체 정보(묶음별 칸) → 4. 점검 결과(판정 타일 = 필터, 구분별 카드 2열) → 5. 판정기준 자료(탭: 입찰 점수기준·법정 의무 기준표·근거 문서·내려받기)
- 공통 스타일 예외와 이유: 판정 상태를 카드 왼쪽 4px 띠와 문구 배지로 함께 표시(성공·오류·DEMO 노랑·회색 토큰). 색만으로 구분하지 않는다

## 입력과 결과

| 항목 | 결정 내용 |
|---|---|
| 입력 | 하려는 일(공공 건설공사 입찰·공공 용역 입찰·공공 물품 납품·공공기관 현장 작업), 업체 설명(600자, 선택), 업체 프로필 34칸(모르면 '모름') |
| 주요 행동 | 'AI로 업체 정보 채우기' → 제안 칸별 체크 → '고른 n개 적용'. 판정은 입력이 바뀌면 바로 다시 |
| 결과 형식 | 판정 타일 4개(부족·확인 필요·충족·해당 없음, 누르면 필터), 구분별 항목 카드: 판정·점수·이유·영향·준비할 것·근거(문서·위치·시행일·원문 인용·원문 링크) |
| 다운로드 | 내 점검 결과 CSV(브라우저에서 생성), 기준 자료 파일별(점수기준·의무 기준표·판정 항목·인용·근거 문서·스키마)과 전체 zip |
| 근거·출처 | 항목마다 원문 인용. 인용은 데이터셋을 만들 때 원천 파일 원문과 대조해 하나라도 없으면 생성 실패 |
| 자료 전송·보관 | 판정은 브라우저. AI 버튼을 누를 때만 설명이 Anthropic으로 전송(전화·이메일·사업자번호는 서버가 가림). 설명은 저장하지 않음(예산 기록만) |
| 로그인·권한 | `/demo/` 공통 관문을 따름 |

## 실제 연결 범위

- 실제로 작동하는 기능: 기준 JSON·내려받기(고정 digest), 판정, AI 프로필 채우기(Claude Sonnet 5.5, 하루 `PUBLIC_OHS_AI_DAILY_KRW` 2,000원·기기당 20회는 지원사업 AI와 공유 카운터)

## 결정과 검증

- 사용자 결정: 판정기준·점수기준·법령을 구분해 내려받게 공개, 기준을 골라 보며 내 사업장 판정을 옆에 표시, 자연어 → 스키마 → 체크리스트, Family Design 형식
- 임시 가정: 점수는 조달청 기준만(기관별 기준은 입찰공고 우선으로 안내), 매뉴얼 평가표는 '예시'로 표기, 점수 합계는 표시하지 않음(반영 비율이 기준마다 달라서)
- 검증: vitest(판정 규칙·업종 기준·실제 데이터셋 필드), pytest(digest 고정·내려받기 허용 목록·관문·AI 스키마 밖 값·근거 없는 값·마스킹·한도), 미리보기 관문에서 Playwright(AI 제안→적용→결과·기준표 내 판정, 360px 가로 넘침 0)
- 운영 배포 여부: 2026-10-01 반영. 공개 주소에서 화면·기준 JSON·zip·CSV 내려받기 200, 브라우저 오류 없음 확인. 공개 주소에서 실제 AI 요청은 보내지 않음
