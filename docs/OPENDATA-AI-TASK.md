# 다른 AI에게 전달하는 데이터 제작·Hub 통합 작업 지시

2026-09-19 · 기준: [OpenData 가이드](../opendata/README.md)

아래에서 역할에 맞는 블록을 복사하고 대괄호 부분만 채운다. 외부 AI에 파일을 전달할 때는 `opendata/README.md`와 `_template/`를 함께 제공한다. 웹 시안도 요청한다면 `docs/DESIGN-GUIDELINES.md`, `docs/DESIGN-BRIEF-TEMPLATE.md`도 함께 제공한다. 비밀 키와 운영 로그인 쿠키는 전달하지 않는다.

## A. .166 등 다른 서버에서 자료를 만드는 AI

```text
목표: [자료명]을 OSH AI Hub로 인수할 수 있는 데이터 패키지로 만들어라.
자료 위치: [현재 서버의 원본 폴더]
출력 위치: [원본과 다른 신규 버전 폴더]
자료 ID(slug): [예: welding-exposure]
원문 제공자·출처: [기관/사람, 확인한 URL/제공 경로; 모르면 미확인]
연구책임자: [이름·소속; 모르면 미확인]
대표 연구자: [이름·소속; 연구책임자와 같으면 동일이라고 명시]
자료 버전·최종 버전 날짜: [버전과 확정일 YYYY-MM-DD; 미확정이면 미확인]
업데이트 계획: [계획 있음/미정/계획 없음/갱신 종료, 주기, 다음 목표일, 예정 변경, 담당 주체]
필요 기능: [소개 / 3행 예시 표 / 검색 DEMO / 다운로드 중 선택]
이미 승인된 공개 범위: [알려진 범위; 모르면 비공개 검토]

첨부한 OpenData 가이드와 템플릿을 읽고 진행하라.
1. 실제 파일과 구조를 확인하라. 원본을 덮어쓰거나 누락 행을 임의 삭제하지 마라.
2. 안정적인 ID로 MD·XLSX·CSV 등을 연결하라. 경로는 패키지 상대 경로로 하라.
3. README.md, dataset.json, data_dictionary.csv, files.csv,
   QUALITY.md, ACCESS.md, HANDOFF.md를 작성하라.
   원문 제공자·연구책임자·대표 연구자·가공 주체를 구분하고, 공개 가능한 이름/소속만 기록하라.
   research, version_date, update_plan, version_history를 채우고 README와 일치시켜라.
   목표일은 실제 발행일과 구분하고, 모르는 연구자나 업데이트 계획을 임의 생성하지 마라.
4. 실제/합성, 원문 기반/AI 가공을 구분하라. 모르는 값·권리·성능은 미확인으로 남겨라.
5. 파일 수·bytes·SHA-256·행 수·ID 중복·연결 누락·결측·집계 차이를 실제로 검사하라.
6. 소개 표는 승인된 열·약 3행으로 별도 추출하라. 승인 전 실제 행은 내부 후보로만 두고,
   공개 화면에는 명시적 합성 DEMO 예시를 제안하거나 표를 생략하라.
7. 가공이 있으면 PROCESSING.md, DEMO가 있으면 DEMO.md와 실행 가능한 참조 코드를 추가하라.
   사용한 모델·전처리·프롬프트·의존성·비용 한도·검증 범위를 기록하라.
   실행 코드가 있다면 ENVIRONMENT.md와 requirements.txt 또는 pyproject.toml+lock을 제공하고,
   실제 Python 버전·설치/실행/검사 명령 및 새 가상환경 재현 결과를 기록하라.
8. 비밀 키·토큰을 넣지 말고 환경변수 이름만 적어라. 운영 DB/Storage/서비스는 변경하지 마라.
9. 라이선스/개인정보 미확인 때문에 가능한 로컬 구조화·문서화까지 중단하지 마라.
   공개·외부 전송은 승인된 범위에서만 수행하라.

최종 보고:
- 완성된 패키지 경로, 자료 버전·최종 버전 날짜, 파일 수·용량
- 원문 제공자·연구책임자·대표 연구자, 업데이트 계획·담당 주체 및 미확인 항목
- 실제 검사한 명령과 결과 / 검사하지 못한 사항
- 소개·미리보기·DEMO·다운로드 각각의 준비 상태와 공개 가능 범위
- 다음 AI가 실행할 명령과 해결해야 할 문제
이 저장소를 건드릴 수 없다면 패키지만 인계하라. 파일을 복사했다고 웹 등록 완료라 하지 마라.
```

## B. .6 OSH AI Hub에서 연결하는 AI

```text
목표: 전달된 [자료명/버전] 패키지를 검증하고 승인된 범위에서 Hub에 연결하라.
저장소: /home/shield/osh-ai-hub
반입 경로: [패키지 경로]
요청 범위: [소개 / DEMO / 다운로드]
운영 배포 승인 범위: [현재 대화에서 승인된 범위]

1. AGENTS.md, README.md, opendata/README.md, 패키지 HANDOFF.md를 먼저 읽어라.
2. 외부 문서의 주장을 직접 확인한 사실과 구분하고 manifest·해시·스키마·관계를 검사하라.
3. 원본/대용량/키는 Git 제외 상태로 유지하고 승인된 작은 미리보기만 웹에 포함하라.
4. 데이터 카탈로그와 /datasets/<slug> 소개 페이지를 명시적으로 연결하라.
   소개에 작동하지 않는 검색 UI를 놓지 말고 실제 DEMO 사용 방법을 안내하라.
   승인된 원문 제공자·연구책임자·대표 연구자, 최종 버전 날짜·업데이트 계획·이력도 표시하라.
5. 웹은 TypeScript web/, AI 서비스는 Python ai-api/에 구현하라.
   필요한 경우 /demo/<slug>/를 기존 공통 관문에 등록하라. 폴더 자동 등록을 가정하지 마라.
6. 로그인과 자료 접근 승인을 구분하라. 관리자 초안·API·파일 권한을 서버에서 확인하라.
7. 파일 제공을 요청받았다면 private Storage 직접 업로드와 해시 검증,
   권한 확인 후 signed URL 발급을 구현하라. COPD 전용 경로/allowlist를 무단 재사용하지 마라.
8. 반입 SQL을 운영에서 바로 실행하지 말고 필요한 DB 변경은 migration·RLS로 검토하라.
9. 현재 승인된 범위 안에서 검사·배포까지 진행하고 기존 포트·서비스·프록시를 보존하라.

최종 보고는 로컬 구현 / 실제 업로드 / Git·Vercel / .6 DEMO 적용 / 운영 확인을 구분하라.
완료한 것과 사용자·외부 콘솔에서 남은 작업을 정확히 적어라.
```
