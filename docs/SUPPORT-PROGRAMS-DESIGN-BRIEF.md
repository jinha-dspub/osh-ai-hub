## 목적

- 사용하는 사람: 사업장 안전보건 담당자, 근로자
- 해결할 일 한 가지: 우리 사업장 조건으로 받을 수 있는 지원사업과 확인할 조건을 찾는다
- 도구 설명 한 문장: 사업장을 설명하거나 조건을 고르면 요건표에서 해당하는 지원사업을 골라 준다
- 이번 작업 범위: 제작자 HTML DEMO를 Hub 형식(React + Family Design)으로 다시 구현, 소개 화면

## OSH Family Design 적용

- 적용 키트 버전: OSH Family Design 1.0 (`design/osh-family/osh-family.css`)
- 공통 색상·Noto Sans KR Variable·카드 12px·버튼/입력 7px 적용: 적용. 추가 스타일(`sp-` 접두사)은 키트 토큰만 사용
- 폰트 실제 로드 확인: Playwright `document.fonts.check` 통과(데스크톱·360px)
- 앱에 맞게 달라지는 레이아웃: AI 설명 카드(제안 체크리스트) → 검색·조건 카드 → 요약 타일 → 분류 9개 카드(여러 개 선택) + 받는 방식 4개 버튼 → 사업 카드 2열
- 공통 스타일 예외와 이유: 판정 상태를 카드 위 4px 띠로 구분(성공·DEMO 노랑·파랑·회색 토큰). 색과 함께 `확인 필요`·`해당 안 됨` 등 문구를 반드시 표시

## 입력과 결과

| 항목 | 결정 내용 |
|---|---|
| 입력 | 사업장 설명(500자, 선택), 검색어, 신청 주체, 상시근로자 수, 업종(KSIC 11차 대·중분류), 시·도, 기업 규모, 유해인자 보유 |
| 주요 행동 | 입력이 바뀌면 바로 다시 판정. AI 조건 채우기는 제안 → 칸별 체크 → "고른 n개 조건 적용"으로 사람이 확인해야 반영. AI가 채운 칸에는 `AI` 표시가 남고 사람이 바꾸면 사라진다 |
| 결과 형식 | 요약 타일 + 고른 분류·받는 방식(또는 검색어)의 사업 카드. 검색어와 맞는 사업이 앞, `검색어 일치` 표시 |
| 분류 | Hub 분류 9개(설비개선 15 · 환경개선 5 · 장비지원 6 · 컨설팅 14 · 점검·기술지도 17 · 측정·검진 12 · 교육 4 · 보험료·감면·인증 20 · 건강상담·산재복귀 21). 패키지 원 `지원범주`는 그대로 두고 serving v2의 `categories.csv`로 붙임 |
| 검색 | 거르지 않고 순위만 바꿈. 띄어쓰기·구분 기호 무시, 동의어 묶음(보호구=안전장비, 더위=온열, 협착=끼임 등). 분류를 안 골랐을 때만 일치하는 사업만 보여 줌 |
| AI | Claude Sonnet 5.5(`dever/claude_client.py` 키). 출력은 도구 호출 하나, 서버가 화면 선택지 밖의 값과 설명에 없는 근거 문구를 버림. 지원 가능 여부는 판단하지 않음. 하루 이 서비스 2,000원·기기당 20회 한도, 공용 AI 한도 공유 |
| 다운로드 | 없음(이용 조건 미확인) |
| 근거·출처 표시 | 카드마다 근거 수준 · 공식 페이지 · 신청 링크(새 창), 하단 자료 카드·근거 분포·검사 범위 |
| 자료 전송·보관 | 판정은 브라우저 안에서. 수요 로그(분류·받는 방식·검색어·조건·노출·이동·AI 제안/적용/수정)를 스키마 3 묶음으로 보내 `/nas/osh-support-programs/raw/demand-log-YYYYMMDD/`에 추가 저장. AI 요청은 설명 원문(전화번호·이메일·사업자번호 가림)과 제안을 `<세션ID>-ai-<요청ID>.json`으로 저장하고 Anthropic으로 전송. 화면 첫머리와 버튼 옆에 고지, 버튼 문구 "동의하고 AI로 조건 채우기" |
| 로그인·권한 | DEMO는 `/demo/` 공통 관문(현재 .3에서 인증 없이 열림). 소개도 공개 |

## 실제 연결 범위

- 실제로 작동하는 기능: 요건 판정·검색 순위·분류/받는 방식 다중 선택·AI 조건 채우기·지원품목 펼치기
- DEMO 자료·예시 결과: 화면 전체에 `DEMO · 실제 자료 v0.7` 표시. AI는 조건 제안만 하고 설명문을 만들지 않음. 제안 품질 평가는 하지 않았다(시험 설명 3건만 확인)
- 연결 준비 중: 다운로드, 로그 동기화·가공 정기 실행
- 확인하지 못한 외부 동작: 운영 관문(.6:8103) 재시작 후 최종 URL 응답

## 결정과 검증

- 사용자와 합의한 사항: B안(Hub 형식으로 다시 구현), Hub 디자인을 최대한 따르고 Family Design으로 다시 만든다, 수요 로그 수신이 핵심이며 /nas 규칙대로 저장한다
- 임시 가정: 소개는 관리자로 시작, DEMO는 공개 관문을 따른다
- 사용자 결정이 필요한 핵심 사항: 연구자·이용 조건 확인 후 소개 공개 전환, 로그 파일럿 모집단
- 모바일·키보드·대비 확인: 1440px·360px 가로 넘침 0, 모든 입력에 레이블, 분류·받는 방식 버튼 `aria-pressed`, 요약 `aria-live`, AI 제안 `role=status`
- 코드·브라우저 검증 결과: vitest 판정 규칙(패키지 수치 재현)·로그 묶음/재전송, pytest 관문·해시·열 제한·로그 적재/거부/한도·NAS 잠금, lint·typecheck·build, Playwright 흐름과 가짜 NAS 적재 확인
