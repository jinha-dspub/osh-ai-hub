# 안전보건 지원사업 찾기 디자인 브리프

상태: 구현 완료 · 공개 반영 대기 (소개 공개 · DEMO + 수요 로그)
작성일: 2026-10-01
기준: [OSH AI Hub 디자인 가이드](DESIGN-GUIDELINES.md) · 인수 검토: [SUPPORT-PROGRAMS-INTAKE-REVIEW.md](SUPPORT-PROGRAMS-INTAKE-REVIEW.md)

## 목적

- 사용하는 사람: 사업장 안전보건 담당자, 근로자
- 해결할 일 한 가지: 우리 사업장 조건으로 받을 수 있는 지원사업과 확인할 조건을 찾는다
- 도구 설명 한 문장: 상시근로자 수와 업종을 넣으면 요건표에서 해당하는 지원사업을 골라 준다
- 이번 작업 범위: 제작자 HTML DEMO를 Hub 형식(React + Family Design)으로 다시 구현, 소개 화면

## OSH Family Design 적용

- 적용 키트 버전: OSH Family Design 1.0 (`design/osh-family/osh-family.css`)
- 공통 색상·Noto Sans KR Variable·카드 12px·버튼/입력 7px 적용: 적용. 추가 스타일(`sp-` 접두사)은 키트 토큰만 사용
- 폰트 실제 로드 확인: Playwright `document.fonts.check` 통과(데스크톱·360px)
- 앱에 맞게 달라지는 레이아웃: 검색·조건 카드 → 요약 타일 4개 → 세 갈래 카드 → 갈래 지도(뿌리 + 연결선 + 종류 버튼) → 사업 카드 2열
- 공통 스타일 예외와 이유: 판정 상태를 카드 위 4px 띠로 구분(성공·DEMO 노랑·파랑·회색 토큰). 색과 함께 `확인 필요`·`해당 안 됨` 등 문구를 반드시 표시

## 입력과 결과

| 항목 | 결정 내용 |
|---|---|
| 입력 | 검색어, 신청 주체, 상시근로자 수, 업종(KSIC 11차 대·중분류), 시·도, 기업 규모, 유해인자 보유 |
| 주요 행동 | 입력이 바뀌면 바로 다시 판정. 별도 실행 버튼 없음. 예시 조건 4개는 보조 버튼 |
| 결과 형식 | 요약 타일 + 고른 지원 종류의 사업 카드(받을 수 있는 것 → 조건에 안 맞는 것) |
| 다운로드 | 없음(이용 조건 미확인) |
| 근거·출처 표시 | 카드마다 근거 수준 · 공식 페이지 · 신청 링크(새 창), 하단 자료 카드·근거 분포·검사 범위 |
| 자료 전송·보관 | 판정은 브라우저 안에서. 수요 로그(갈래·종류·검색어·조건·노출·이동)를 묶음으로 보내 `/nas/osh-support-programs/raw/demand-log-YYYYMMDD/`에 추가 저장. 이름·연락처·사업장명·IP 없음. 화면 첫머리 수집 고지 |
| 로그인·권한 | DEMO는 `/demo/` 공통 관문(현재 .3에서 인증 없이 열림). 소개도 공개 |

## 실제 연결 범위

- 실제로 작동하는 기능: 요건 판정·검색·두 단계 드릴다운·지원품목 펼치기
- DEMO 자료·예시 결과: 화면 전체에 `DEMO · 실제 자료 v0.7` 표시. AI 생성 설명 없음
- 연결 준비 중: 다운로드, 로그 동기화·가공 정기 실행
- 확인하지 못한 외부 동작: 운영 관문(.6:8103) 재시작 후 최종 URL 응답

## 화면 상태

| 상태 | 표시 문구 | 가능한 행동 |
|---|---|---|
| 초기 | 요건표를 불러오는 중입니다… | 대기 |
| 갈래 선택 전 | 위에서 하나를 고르면 그 안의 지원 종류가 나옵니다 | 갈래 선택 |
| 종류 선택 전 | 지원 종류를 하나 고르면 사업이 펼쳐집니다 | 종류 선택 |
| 성공 | 받을 수 있는 N건, 조건에 안 맞는 M건은 끝에 흐리게 | 공식 페이지·신청하기 |
| 빈 결과 | ○○에는 이 조건으로 걸리는 사업이 없습니다 + 바꿀 입력 | 검색어·조건 변경 |
| 실패 | 자료를 불러오지 못했습니다 | 다시 불러오기 |

## 결정과 검증

- 사용자와 합의한 사항: B안(Hub 형식으로 다시 구현), Hub 디자인을 최대한 따르고 Family Design으로 다시 만든다, 수요 로그 수신이 핵심이며 /nas 규칙대로 저장한다
- 임시 가정: 소개는 관리자로 시작, DEMO는 공개 관문을 따른다
- 사용자 결정이 필요한 핵심 사항: 연구자·이용 조건 확인 후 소개 공개 전환, 로그 파일럿 모집단
- 모바일·키보드·대비 확인: 1440px·360px 가로 넘침 0, 모든 입력에 레이블, 갈래·종류 버튼 `aria-pressed`, 요약 `aria-live`
- 코드·브라우저 검증 결과: vitest 판정 규칙(패키지 수치 재현)·로그 묶음/재전송, pytest 관문·해시·열 제한·로그 적재/거부/한도·NAS 잠금, lint·typecheck·build, Playwright 흐름과 가짜 NAS 적재 확인
- 운영 배포 여부: 하지 않음
