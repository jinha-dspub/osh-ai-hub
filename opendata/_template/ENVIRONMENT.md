# 실행 환경·패키지 인계

현재는 **DEMO 문서·합성 데이터 양식**이며 실행 앱이 없다. 동봉한 requirements.txt는 주석만 있는 양식으로, 실행 환경이 완성되었다는 뜻이 아니다. 데이터만 전달할 때는 실행 의존성이 해당 없음이라고 기록한다.

## Python 코드가 있다면 반드시 작성

| 항목 | 실제 확인한 내용 |
|---|---|
| Python 버전 | 미확인 · 실제 실행한 전체 버전 |
| 운영체제·아키텍처 | 미확인 |
| 의존성 관리 | requirements.txt 또는 pyproject.toml + 해당 도구의 lock 파일 |
| 실행할 스크립트 | 미구현 · 실제 파일의 상대 경로 |
| 입력·출력 경로 | 미확인 · 원본을 덮어쓰지 않는 출력 위치 |
| 설치·실행·검사 명령 | 미실행 · 아래 양식에서 실제 명령으로 교체 |
| OS 패키지·외부 프로그램 | 해당 여부 확인 필요. 필요한 경우 이름·버전·설치 방법 |
| GPU/CUDA·모델 파일 | 해당 여부 확인 필요. 필요할 때만 버전·모델 ID·획득 방법 |
| 환경변수 | 필요한 이름·용도만 기록. 키·토큰 값 금지 |
| 재현 결과 | 새 가상환경에서 성공/실패/미검사와 날짜·근거 기록 |

## requirements.txt를 선택했을 때의 설치 양식

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
```

위 명령은 환경 생성·설치 양식이다. 현재 주석뿐인 파일을 설치해도 실행 앱이 생기지 않는다. 실제 처리·검증 명령은 제작자가 추가한다.

- 사용하는 외부 패키지만 넣고 실제 검증한 버전을 고정한다. XLSX를 읽는 코드가 있다면 그 코드에서 사용하는 엔진도 포함한다.
- 공유 서버의 전체 pip freeze를 그대로 전달하지 않는다. 새 가상환경에서 필요한 패키지만 설치해 재현을 확인한다.
- pyproject.toml을 사용하면 대응 lock 파일과 실제 사용한 도구 버전·설치 명령을 함께 준다. 두 방식을 모두 유지할 필요는 없다.
- Python 표준 라이브러리만 사용하면 외부 패키지 없음이라고 명시하고 Python 버전과 실행 명령을 남긴다.
- 패키지 파일에 키가 포함된 URL·서버 절대 경로를 넣지 않는다. .venv와 다운로드한 모델은 패키지/Git에 넣지 않는다.
- JavaScript 참조 앱은 package.json과 대응 lock 파일, Node 버전·설치/실행 명령을 전달한다.
