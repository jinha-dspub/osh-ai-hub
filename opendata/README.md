# OSH AI Hub 데이터 패키지 제작·인수 가이드

버전 1.1 · 2026-09-19 · 대상: 다른 서버에서 자료를 만드는 AI와 Hub에 연결하는 AI

**자료 제작자는 데이터와 설명·검증 결과를 한 패키지로 전달하고, Hub 통합자는 그 패키지를 확인한 뒤 소개 화면·DEMO·다운로드를 연결한다.** COPD를 참고하되 각 자료의 공개 조건과 구조를 따로 판단한다.

이 문서는 앞으로 사용할 인수 규약이다. `dataset.json`을 읽어 자동 등록하는 기능이나 범용 업로더가 이미 구현됐다는 뜻은 아니다. 현재 COPD는 개별 코드로 연결되어 있다.

## 1. 다른 서버에서 무엇을 만들면 되는가

| 제작 목표 | 필요한 결과 | 없어도 되는 것 |
|---|---|---|
| 자료 반입·보관 | 실제 자료 + 아래 필수 설명 파일 7개 | 웹앱, 임베딩, SQL 덤프 |
| 데이터 소개 | 출처·기간·단위·활용법·실측 통계 + 소개 공개 범위 | 검색 기능 |
| Excel 같은 예시 표 | 공개 가능한 열을 선택한 `preview.csv`, 보통 3행 | 전체 원본의 웹 복사 |
| 검색 DEMO | 연결 키가 있는 정규화 데이터, 검색 조건·결과 명세, 실행/검증 방법 | 유료 AI, 벡터 검색, 답변 생성 |
| 의미 검색 | 위 결과 + 임베딩 파일과 모델·입력·차원 명세 | PostgreSQL 덤프 |
| 파일 다운로드 | 배포할 파일 목록·버전·해시·권한 + 실제 업로드 검증 | Hugging Face 게시 |

처음에는 **키워드·필터·원문 확인**이 되는 작은 DEMO면 충분하다. AI 설명과 임베딩은 필요할 때 추가한다. 검증되지 않은 기능·정확도·비용을 채우려고 만들지 않는다.

## 2. 패키지 폴더 표준

`<slug>`는 영문 소문자·숫자·하이픈으로 정한다. 예: `copd`. 파일의 연결은 행 순서가 아니라 안정적인 ID를 사용한다.

```text
opendata/<slug>/
  README.md                 # 필수: 사람이 읽는 데이터 카드
  dataset.json              # 필수: ID·버전·상태·파일/표 연결 메타데이터
  data_dictionary.csv       # 필수: 열 의미·타입·단위·결측·출처
  files.csv                 # 필수: 데이터/인덱스/배포 파일 크기·해시 목록
  QUALITY.md                # 필수: 실제 검사 결과와 미검증 항목
  ACCESS.md                 # 필수: 출처·권리·개인정보·기능별 공개 범위
  HANDOFF.md                # 필수: 다음 AI의 시작점과 미완료 작업
  preview.csv               # 소개 표를 제공할 때: 승인된 열·약 3행
  DEMO.md                   # DEMO가 있을 때: 입력·API·화면·실행·실패 상태
  PROCESSING.md             # 가공했을 때: 변환 규칙·재현 방법·모델 기록
  data/                     # 정규화 표: records.csv, texts.csv 등
  raw/                      # 반입 원본: MD, XLSX, PDF 등; 덮어쓰지 않음
  indexes/                  # 선택: embeddings.parquet 등
  scripts/                  # 선택: export, validate, preview 생성 코드
  reports/                  # 권장: 검증 결과, 재집계 STATS.json
  demo/                     # 선택: 외부 제작자의 참조 구현
  release/                  # 다운로드할 때: 확정 CSV/ZIP/XLSX 등
```

필수 파일의 **존재**와 내용의 **검증 완료**는 다르다. 모르는 항목은 `null` / `미확인`으로 기록하고 초안으로 인수할 수 있다. 빠진 정보를 임의로 채워 공개하지 않는다. 전체 폴더가 동일 버전의 스냅샷이어야 하며 변경 시 새 버전으로 내보낸다.

복사 가능한 시작점: [`_template/`](./_template/README.md). 다른 AI에게 줄 작업 지시: [제작·통합 프롬프트](../docs/OPENDATA-AI-TASK.md).

## 3. 필수 설명 파일 7개

| 파일 | 반드시 포함할 정보 |
|---|---|
| `README.md` | 무엇을 다루는가, 누가/어디서 만들었는가, 포함·제외 기준, 기간, 한 행의 의미, 실제 파일 목록, 읽는 법, 활용 예, 한계, 인용, 원문 제공자·연구책임자·대표 연구자, 최종 버전 날짜·업데이트 계획·변경 이력 |
| `dataset.json` | 규약 버전, slug, 자료 버전, 실제/합성 여부, 초안 상태, 원문 출처와 가공 주체, 연구책임자·대표 연구자, 버전 날짜·업데이트 계획·이력, 표의 키·관계, 확인된 통계, 소개·표·DEMO·다운로드 각각의 상태 |
| `data_dictionary.csv` | 표 경로, 열 이름, 설명, 타입, 결측 허용·표현, 단위, 허용 값, 원문/AI/계산/검수 출처, 연결 키, 공개 검토 상태 |
| `files.csv` | 상대 경로, 고정 파일 ID, 역할·형식, bytes, SHA-256, 표의 데이터 행 수(헤더 제외), 파일 접근 수준 |
| `QUALITY.md` | 검사한 버전·날짜·명령, 합격/실패/미검사, 중복·결측·키 연결·집계 일치, 불일치 원인/미확인, 별도 내용 검수 범위 |
| `ACCESS.md` | 원문·가공물 각각의 이용 조건과 근거, 개인정보 검수 범위, 소개/표/검색/원문/다운로드 대상, 승인 근거와 미정 사항 |
| `HANDOFF.md` | 전달 버전, 무엇을 실행했고 무엇을 안 했는가, 재현 명령, 필요한 환경변수 이름만, 미해결 문제, Hub에서 연결할 위치 |

파일 목록에는 실제 전달된 데이터·미리보기·인덱스·배포 파일을 빠짐없이 포함한다. `files.csv` 자체 및 설명 문서는 해시 목록에서 제외해 자기 참조를 피한다. 보안 점검은 설명 문서·스크립트까지 포함한 **전체 패키지**에 적용한다. 반입 압축본의 해시는 압축본 바깥의 인수 기록에 남긴다.

### 출처·연구자·버전 관리 필수 항목

소개 카드와 `dataset.json`에 다음 정보를 함께 기록한다. 모르는 값은 미확인/null로 두고 HANDOFF에 확인할 항목으로 남긴다.

| 항목 | 기록 기준 |
|---|---|
| 원문 제공자 | 원자료를 제공한 기관/사람과 원문 URL. `sources`의 각 항목에 `provider`, `title`, `url`, `collected_on` 기록. 복수 출처는 각각 작성 |
| 연구책임자 | `research.principal_investigator`: `name`, `affiliation`. 연구 책임을 맡는 사람 |
| 대표 연구자 | `research.lead_researcher`: `name`, `affiliation`. 자료 소개에 대표로 표시할 연구자. 연구책임자와 동일해도 각 역할에 명시 |
| 가공 주체 | `processing_owner`. 실제 데이터 정리·추출·AI 가공 담당 주체. 원문 제공자와 구분 |
| 공개 문의처 | `research.public_contact`: 공개 가능한 연구팀 이메일 또는 문의 URL. 개인 연락처를 임의 공개하지 않음 |
| 최종 버전 날짜 | `version_date`: 현재 `version`을 확정한 날짜, `YYYY-MM-DD`. 조사 기간·수집일·업로드 시각·파일 mtime과 구분 |
| 업데이트 계획 | `update_plan`: 상태, 주기, 다음 버전, 목표일, 예정 변경, 갱신 담당, 비고 |
| 변경 이력 | `version_history`: 버전별 `version`, `date`, `changes`. 자료 추가·정정·열/연결 키 변경 등을 기록 |

`update_plan.status`는 `planned`(계획 있음), `undecided`(미정), `none`(계획 없음), `ended`(갱신 종료)다. `frequency`는 월별/분기별/비정기 등 실제 계획, `next_version`은 예정 버전, `next_target_date`는 목표 날짜 또는 null, `planned_changes`는 변경 목록, `maintainer`는 갱신 담당 주체, `note`는 사유·불확실성을 적는다. 목표일은 완료된 발행일로 표시하지 않는다. 계획 없음과 미정을 구분하고, 계획 없음/종료라면 다음 버전·목표일을 비운다.

책임자·대표 연구자를 로그인 계정, 저장소 소유자 또는 원문 제공자 이름에서 추정하지 않는다. 실제 이름과 소속은 제공받거나 확인한 정보만 쓴다. 가이드 작성 AI가 연구책임자가 되는 것은 아니다. 공개 승인을 받은 담당자 정보만 소개 화면에 옮긴다.

## 4. MD + XLSX를 연결해 보낼 때

- XLSX를 원본으로 유지하고 기계 처리를 위한 UTF-8 CSV 또는 Parquet를 함께 제공한다. 시트명·표 시작 행·수식/병합 셀 처리 규칙을 기록한다.
- 기본 표에 `record_id`와 `source_path`를 둔다. `source_path`는 패키지 루트 기준 `raw/md/파일.md` 같은 상대 경로다. 서버 절대 경로를 저장하지 않는다.
- 원문이 여러 개인 자료는 `documents.csv`의 `document_id, record_id, source_path`로 1:N 관계를 표현한다. 한 셀에 경로를 임의로 이어 붙이지 않는다.
- ID는 문자열로 읽는다. 선행 0·긴 번호가 Excel에서 손실되지 않게 하고 날짜·단위·소수점 변환 규칙을 기록한다.
- 경로는 대소문자·한글 정규화·중복 파일명을 검사한다. 패키지 바깥을 가리키는 `..`, 절대 경로, 심볼릭 링크는 반입 경로로 허용하지 않는다.
- XLSX의 각 ID가 실제 MD에 연결되는지, MD만 있고 표에 없는 문서가 있는지, 연결이 중복되는지 개수를 보고한다. 연결 실패를 조용히 버리지 않는다.
- CSV 안에 줄바꿈이 들어갈 수 있으므로 줄 수로 행 수를 세지 않는다. MD의 HTML은 웹에서 안전하게 렌더링한다.
- Excel용 다운로드는 수식 주입(`=`, `+`, `-`, `@` 등) 처리 규칙을 둔다. 원본을 바꾸지 않고 별도의 안전한 배포본과 변경 기록을 만든다. 숫자 부호와 문자열을 구분한다.

## 5. 데이터·스키마 규칙

- `(자료 버전, record_id)`로 대상을 식별한다. 측정치·문서·청크는 별도 ID와 부모 키를 가진다. 기존 외부 ID를 유지해야 하면 내부 ID와의 매핑을 비공개로 관리할 수 있다.
- `raw_`는 원문 표기, `src_`는 원문 기반 추출, `ai_`는 AI 가공, `calc_`는 계산, `qa_`는 검수 결과로 구분하는 것을 권장한다. 접두어만으로 정확성·검수 완료를 주장하지 않는다.
- 결측을 0이나 '없음'으로 바꾸지 않는다. 빈 값·미상·해당 없음은 구분하고 boolean·날짜·단위·복수 값 표현을 사전에 정한다.
- 복수 값은 JSON 배열 문자열 또는 별도 관계 표를 권장한다. 기존 구분자를 유지한다면 이스케이프·분리 규칙까지 적는다.
- 모든 열을 사전에 설명한다. 원문 추출값과 AI 결과는 가능하면 문서 ID·절/문단 등 근거로 연결한다. 없는 페이지 번호를 만들지 않는다.
- 통계에는 분모와 단위를 함께 적는다. 값이 채워진 비율은 정확도가 아니며, 행 수와 사람/사건 수는 별개다.
- 학습용 자료라면 중복·같은 사건을 분할 간에 섞지 않고, 결과를 드러내는 필드의 입력 누출을 검사한다. 분할하지 않았으면 명시한다.

### 기계 판독 메타데이터 약속

템플릿의 `dataset.json`은 인수용이며 현재 웹의 자동 설정 파일이 아니다.

- `schema_version`: 이 규약은 `1.1`. 기존 `1.0` 패키지는 새 연구자·버전 관리 항목을 미확인으로 보완하고 재검토한다. `is_template`은 실제 패키지에서 `false`로 변경.
- `id`: 폴더명과 일치. `version`: 날짜 또는 릴리스 식별자, 덮어쓰기 없이 고정.
- `data_kind`: `real`, `synthetic`, `mixed`. `status`: `draft`, `review`, `released`, `archived`.
- `statistics`: 실제 확인한 값만. 아직 계산하지 않은 값은 `null`, 계산 범위와 `evidence` 기록.
- `tables`: 각 파일의 기본키와 외래키. 모든 경로는 패키지 루트 기준.
- `publication`: `introduction`, `preview`, `demo`, `download` 각각 `state`, `audience`, `evidence`.
- `state`: `not_planned`, `draft`, `review`, `ready`. `audience`: `none`, `admin`, `approved`, `public`.
- `ready`는 해당 기능의 필요한 검수·실행 검증과 접근 정책 확인을 마쳤을 때만 사용한다. JSON 값 자체가 권한을 부여하거나 서비스를 공개하지 않는다.
- `not_planned`에는 이유, 미확인에는 `null`을 사용한다. 가짜 URL·성능·담당자·라이선스를 채우지 않는다.

`files.csv`의 `access`는 `restricted`, `reviewed-preview`, `public` 중 하나다. 파일의 실제 공개 여부는 별도 권한 구현으로 강제한다. `rows`는 표일 때만 기입하고 비표 형식은 비운다. ZIP의 해시는 완성된 ZIP 바이트를 기준으로 계산한다.

## 6. 소개 페이지와 예시 표의 기준

소개 페이지는 `/datasets/<slug>`에서 다음 순서로 제공하는 것을 기본으로 한다.

1. 자료명, 한 문장 목적, 실제/합성 표시, 버전·기간·확인된 규모.
2. 원문 제공자·출처 바로가기, 연구책임자·대표 연구자의 이름/소속, 가공 주체와 사용 가능한 범위. 최종 버전 날짜와 업데이트 계획(주기·목표일·예정 변경)을 명시하고 변경 이력을 제공한다.
3. **엑셀처럼 읽는 3행 미리보기**: 명확한 열 제목·행 번호, 모바일 표 내부 스크롤.
4. 활용 순서: 검색 조건 → 원문과 AI 가공 비교 → 허용된 자료 다운로드.
5. 품질·한계, 파일·활용법, 동작하는 DEMO로 이동하는 주요 버튼.

미리보기는 전체 파일을 웹에 넣고 화면에서 3행으로 잘라서는 안 된다. **공개 승인된 열·행만 따로 추출**한다. 원문·요약·사건번호가 공개 가능한지는 별도로 판단한다. 첫 3행, 조건별 3행 등 선택 방식을 표시하고 대표성이 있다고 주장하지 않는다.

표에는 `DEMO 미리보기 · 실제 자료 일부` 또는 `DEMO · 합성 예시`를 표시한다. 공개 가능한 실제 행이 없으면 명시적인 합성 예시를 쓰거나 표를 생략한다. 합성 예시를 실제 통계에 포함하지 않는다.

실제 검색이 다른 DEMO에서만 동작한다면 소개 페이지에 비활성 검색창·필터를 놓지 않는다. 데이터가 없거나 개발 예정인 카드·작동하지 않는 DEMO 링크는 일반 방문자에게 노출하지 않고 관리자 초안에서만 다룬다.

## 7. DEMO·AI 기능을 함께 만드는 경우

`DEMO.md`에 사용자 목적, 입력, 결과, 필터, 요청·응답 예, 실행·종료 방법, 상태 표시, 접근 권한을 적는다. 참조 앱이 있다면 실행 파일과 의존성 버전을 함께 전달한다. 참조 앱을 운영에 그대로 올렸다고 간주하지 않는다.

| 항목 | 인수 기준 |
|---|---|
| 기본 검색 | 키워드·실제 필드 기반 필터·페이지네이션, 결과 없음 처리 |
| 다중 선택 | 같은 필터의 여러 값은 OR, 다른 필터끼리는 AND를 기본 제안으로 명세; 미구현이면 명시 |
| 결과 수 | 전체 조건 일치 건수와 의미 검색 상위 N건을 구분 |
| 상세 | 원문·AI 가공·검수 상태·근거를 구분, URL/파일 ID 입력을 검증 |
| 오류 | 잘못된 입력·권한 없음·시간 초과·서버 오류·예산 소진 시 재시도/대안 안내 |
| 접근성 | 입력 레이블·키보드·포커스·오류 알림·360px 모바일 확인 |
| 보안 | UI를 숨기는 데 그치지 않고 API·상세·검색 요약·파일 모두 서버에서 권한 검사 |

API 계약에는 메서드·경로·요청 타입·상한·응답 필드·오류를 적는다. 기존 COPD의 `action` API를 모든 새 자료가 그대로 따라야 하는 것은 아니다. 웹과 서버 사이에서 합의한 계약을 한 문서에 기록한다.

임베딩을 전달한다면 `indexes/README.md`에 모델의 정확한 ID/리비전, 차원, 문서·질의 작업 설정, 전처리·청크 방식, 입력 텍스트 해시, 행/청크 연결 키, 정규화 방식, 생성 날짜, 재생성 방법을 적는다. 같은 차원이라도 다른 모델의 벡터를 섞지 않는다. 임베딩·요약도 원문에서 파생한 자료로 접근 범위를 검토한다.

AI 가공 시 제공자·모델·프롬프트 버전/해시·생성 시점·사람 검토 범위·실패 행을 기록한다. 외부 API에 어떤 자료가 전송되는지 적고 전송 가능한 범위에서만 사용한다. 키는 환경변수 또는 서버의 `local_asset/`에서 읽으며 패키지에 넣지 않는다.

유료 호출은 기존 공유 예산 체계와 연결하고 일일 한도·동시성·시간 초과·재시도·캐시·한도 도달 동작을 검증한다. 새 DEMO별 한도가 기존 전체 한도를 우회하면 안 된다. 고정 호출 수를 금액 보장으로 표현하지 않는다. 성능 지표는 평가셋·분모·버전·실행 조건이 있을 때만 표시한다.

## 9. 저장·Git·배포 원칙

- raw/정규화 원본/인덱스/ZIP/개인정보/키는 일반 웹 Git 저장소에 올리지 않는다. 원본은 승인된 비공개 저장소·서버, 배포 파일은 object storage에 둔다.
- 이 저장소의 `opendata/.gitignore`는 신규 데이터 폴더를 기본 제외한다. 공개 문서·검토된 작은 미리보기·소스 코드만 명시적으로 추적한다. 새 규칙을 우회하는 `git add -f`로 원본을 넣지 않는다. `.gitignore`는 이미 추적된 파일을 보호하지 않는다.
- 소개에 필요한 작고 검토된 메타데이터만 `web/`에 반영한다. 약 300MB 등 큰 파일은 Storage로 직접 전송하고 웹 함수가 중계하지 않는다.
- 자료별 bucket 또는 prefix는 통합 단계에서 정한다. 불변 버전 경로와 해시를 사용하고, 실제 전송 후 재다운로드 해시를 확인한다.
- private 파일은 서버 권한 확인 후 짧은 signed URL을 발급한다. 클라이언트가 임의 객체 경로를 지정하거나 signed URL을 영구 문서에 저장하지 않게 한다.
- Hugging Face 게시는 현재 계획 없음. 원본 README에 loader 예시가 있어도 실제 게시된 URL로 안내하지 않는다.
- 외부 생성 스크립트·SQL은 읽고 검토한 뒤 실행한다. 기존 서비스·포트·데이터를 보존한다.

## 11. COPD를 참고할 때의 현재 사실

`opendata/copd` 반입본은 원문 MD+XLSX가 아니라 CSV 3개, 통계·설명, 임베딩·SQL·참조 앱 등으로 구성되어 있다. 기존 점검에서는 사례 2,082개와 측정치 646행/79개 사례를 확인했다. 수치는 해당 반입 버전의 기록이며 새 패키지에 복사하지 않는다.

원본의 README·STATS와 Hub 검토 문서 사이에 측정치 수·품질 표현 차이가 있다. 템플릿으로 삼되 원문 주장·권리·평가 수치를 검증된 사실로 그대로 옮기지 않는다. 현재 공개 소개 표는 선택된 네 열의 3행이며, 전체 CSV를 웹에 싣지 않는다. 원본 다운로드는 private Storage를 사용한다.
